# Release checks

- [ ] Review the MIT license choice for code you have the right to license; third-party data are excluded.
- [ ] Run the lightweight verification commands and inspect the archived summary tables.
- [ ] If publishing data later, verify the dataset terms and provide the full preprocessing scripts and citations.
- [ ] Confirm the repository contains no accounts, access tokens, local absolute paths, or personal documents.
- [ ] Make the GitHub repository public only after approving the contents.
- [ ] Link the public GitHub repository to Zenodo before creating the first release.
- [ ] Create a tagged GitHub release `v1.0.0` and wait for the Zenodo deposit to obtain its DOI.
- [ ] Insert the actual DOI/URL into the manuscript Code availability statement and corresponding response only after the record exists.
